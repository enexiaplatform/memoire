# M21 — shared workspaces, actors and permissions

Starting green SHA: `cf3e2913b9ca5b9805864d8e5b637c2932f4e512`.

The ownership audit found that existing Kernel records belong to individual accounts, and M16's responsible-person labels do not prove authenticated authority. M21 preserves that personal boundary. A new owner-governed workspace configuration selects exact existing promises and invites authenticated actors as readers or reviewers. Invitation is distinct from acceptance. Members accept through their own account; readers get a bounded view and reviewers can record actor-attributed review Events. Neither role can rewrite the owner's canonical commercial state.

Configuration is the only new mutable canonical aggregate. It uses the existing versioned repository, required State Revisions, owner RLS, sample isolation, export registry and transactional history restore. Backup format 15 carries this source. Runtime access additionally requires a database-generated epoch and current actor acceptance. Membership/lifecycle changes and actual restore generate a fresh epoch, so restored old Events cannot silently reactivate authority. Original private-table RLS is unchanged. Member response/review Events are immutable, scoped and idempotent by request identity; they are not Evidence or Decisions.

Review gains a folded Shared workspaces panel. Owners preview exact people/roles/promises and explicitly confirm configuration. The panel distinguishes browser persistence from synchronized access. Connected members refresh invitations, accept or decline, read selected public promise fields and, when authorized, record reviews. No invitation email, organization directory, new primary navigation or monitoring score is introduced. Member readings remain transient and disclose their last-refresh limitation.

Six database tests cover populated upgrade, preserved existing history, required workspace revisions, two-owner/private-table isolation, real actor acceptance, reader/reviewer boundaries, role changes, revocation, anonymous denial and full history restore with epoch rotation. Four domain tests cover confirmation, stale/foreign/sample references, failed required-history rollback, local history cutoffs and backup/codec durability. The full durability inventory includes the new aggregate. Owner browser verification passed explicit selected sharing, local-only truthfulness, reload, retirement and narrow layout. Member browser verification exercised the actual migrated permission functions using fixture identity and an HTTP transport, including acceptance, minimal disclosure, review and decline. Time Machine browser regression passed.

Full repository verification passed: build, API type checking, lint, all 1,958 unit/database tests and every contract check. **GO for M22**. Production remains **PRODUCTION DEPLOYMENT PENDING**. The bounded design retains one immutable owner, two member roles, at most 20 members/50 shared promises and a capped current invitation/review view. Broad entity sharing, ownership transfer, offline member access, organization identity and email invitations remain non-goals. Revocation cannot erase information a member already viewed or copied.
