# Ask Memoire: optional AI chat

User decision: 2026-10-16. Implementation scope: a floating conversation throughout the app, plus the full Chat AI page in Search & Insights.

## Behavior

- Open the Ask Memoire chat button from any app screen, or Search & Insights → Chat AI (`/app/ask?mode=ai`). The floating window is full-screen on phones and compact on desktop, with the composer kept visible.
- Select relevant workspace records, a confirmed account ID, or an opportunity.
- Review the exact context preview and choose to share it before sending. The server checks the selected source IDs using the caller's JWT and existing RLS. No service-role access is used.
- Chat supports English/Vietnamese, multiple turns, deal analysis, follow-up drafts, source links, missing evidence and suggested next questions.
- Drafts are copy-only. A proposed plan item has editable text and date and requires an explicit confirmation through the existing Plan store.
- Conversation and consent live in page memory. Minimizing the floating window and navigating inside the app preserve them. Closing and clearing, signing out, reloading, changing scope or starting a new conversation clears them. Only the last four exchanges accompany the next question.
- Local insights and Capture remain operational without AI. Provider failures never turn into invented answers or an automatic switch to a paid model.

## Data and calculation boundaries

Full-scope business tools calculate this week's Plan/follow-ups, quarterly forecast, catalog-linked brand performance or a workspace overview before retrieving up to five detailed opportunities and related snippets. Detailed source records are capped at 24 including a link to the calculated view. Raw capture notes, account notes and attachments are excluded. Free-text summaries may still contain customer names, prices or contact details; inspect the preview before sharing.

The server checks direct record ownership and that sources are not deleted or sample records. Aggregate analysis cards are browser-calculated snapshots, not independent server evidence. It does **not** independently validate each browser field against the latest cloud value or recalculate browser totals. The UI, prompt and privacy policy name that limit. An unsynced/deleted/foreign direct source stops the request before anything reaches Groq. Other conversation text is user-provided input.

Forecast reads the existing quarter allocations, close-period rules and declared/evidence-adjusted probabilities across the scoped book. Brand movement is explicitly recorded Won estimated value for matched month-to-date windows, grouped by confirmed catalog IDs. It does not claim historical pipeline movement without snapshots. Weekly follow-ups reuse Plan and preserve recorded channels; a follow-up with no channel is not presented as an already scheduled visit.

Money facts reuse `buildOrderBook` and `buildReceivables`, with explicit quote-to-opportunity links and the current workspace reporting currency and planning FX settings. Missing money/FX is preserved as unavailable. If all linked money evidence does not fit, no partial money total is supplied. Retrieved subsets are labelled; they must never be presented as full-workspace totals or realized revenue. Period comparisons need actual historical evidence; the model must report missing evidence rather than infer a trend.

Account scope excludes opportunities without a confirmed `accountId`, even when their free-text customer names match. The user can choose such an opportunity directly.

## Operator setup

Set these on the server, in ignored `.env.local` for development or the deployment environment:

```dotenv
AI_CHAT_ENABLED=true
GROQ_API_KEY=<server-only key>
```

No key is included in source code, browser configuration, screenshots or logs. No additional AI SDK or database migration is needed. Vite serves the same handler at `/api/ai-chat`; Vercel rewrites it to the existing `api/commercial.ts` dispatcher. This keeps the deployment within its 12-function Hobby cap.

Use a Groq Free Plan account and review/configure Data Controls, including Zero Data Retention as appropriate. Groq documents these at https://console.groq.com/docs/your-data and Free Plan limits at https://console.groq.com/docs/rate-limits. The app cannot make a paid account free or guarantee a permanent free quota. There is no automatic retry or provider/model fallback.

The fixed model is `openai/gpt-oss-20b`, using strict structured output, a bounded input, 2,400 maximum output tokens and a 25-second timeout. App limits are six requests/minute and 30/day per verified user **per running server instance**, plus the existing address bucket. These in-memory counters reset on cold starts and are not a durable global spending cap; Groq's account-wide quota remains the shared upstream limit.

As of 17 October, chat also supports reviewed batches of Plan creations and open-opportunity edits. See [chat actions](ai-chat-actions-2026-10-17.md) for the supported fields, confirmation and partial-save behavior.

`GET /api/ai-chat` reports configuration only after authentication. It is not proof of a valid provider key, successful inference or available quota. Core production health remains green without AI; enabling chat without a key gives a warning.

## Verification

Automated coverage includes ownership/JWT/RLS query binding, source denial before transmission, consent, system-role and URL injection rejection, source citation validation, history/payload limits, missing configuration, application/provider quota, timeout and non-disclosure of provider errors. Context tests cover sample/foreign filtering, raw-note exclusion, confirmed account IDs, bounded retrieval and missing money.

The local fixture at `node scripts/preview-ai-chat-fixture.mjs` runs the real panel, client and endpoint against explicitly fictional workspace/auth/provider fixtures. It is for browser verification; it does not call Groq or prove live model quality. No fixture route or authentication bypass is shipped in the production build.

Actual live provider acceptance requires an available Groq key. Deployment and a production authenticated browser smoke are separate from local implementation and fixture verification.
