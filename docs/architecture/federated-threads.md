# Federated threads

M26 keeps each party's existing canonical Commercial Thread in its own workspace. A bounded `memoire.federated-thread` v1 exchange connects that local story to a public thread reference and public outcome declaration chosen by the issuer. It carries a declared issuer/recipient pair and one to eight selected M25 capsules already issued or received in the issuer's own workspace. Capsules must concern exactly that pair, have unique statement identities and match sample scope. Exchanges are capped at 20,000 normalized JSON characters and all embedded integrity/signature checks run before product issuance or receipt.

The public reference is an agreed correlation label, not global ownership or verified company identity. Public outcome text is deliberately selected rather than copying the local thread's internal objective. Internal thread, account, Opportunity, private notes, money and canonical promise IDs are excluded. Both directions of capsule claims are permitted, preserving each original issuer and its signed/integrity provenance. The issuing party can relay a selected received capsule, but cannot replace its original content without verification failing. Signatures establish only their own cryptographic checks unless a host separately supplies an agreed issuer-key map.

Only immutable issuance Events are new persisted facts. An Event retains the owner's local thread reference for audit; that reference is omitted from the public exchange. Preview/confirmation reloads current owner/sample storage, validates available sources, refuses stale thread versions and rechecks identity immediately before the durable append. Same-content retry preserves the original fact; identity reuse with differing disclosure conflicts. No mutable federation registry, second authoritative thread, shared cross-company database or State Revision is introduced. The existing Thread remains the canonical local source with its existing history/durability contract.

Recipients confirm their declared reference and receive the full packet as a M17 unaccepted observation. The receipt has no local canonical subject links and grants no access to another party's database. Each party can keep its own local Thread, Evidence, Decision, Conditions and Requirements. An exchange does not grant consensus or resolve anyone else's truth. Counterparty systems can exchange the bounded artifact without using Memoire's database architecture.

`deriveFederatedThreads` groups attributed issued/received exchanges by public reference and sorted declared party pair. It includes only the exact local owner/sample partition and facts recorded by the requested cutoff, using parsed receipt/issuance fact times rather than the remote claimed timestamp. Different public objectives and conflicting content under a statement identity are surfaced explicitly. Invalid stored exchanges make the reading incomplete. No latest remote assertion is silently adopted as canonical state or automatic supersession.

Review has a folded Federated threads panel for selecting a saved canonical thread, public correlation/outcome fields and exact available sources, previewing/confirming issuance, downloading, receiving and reading attributed exchanges. The channel is person-controlled JSON transfer; delivery and acceptance are not claimed. No new primary navigation is added. Ordinary product snapshots do not add envelope-level organization authentication; host-managed signed capsules remain verifiable within them.

The migration adds an invoker immutability/shape guard to the existing private Event table. It validates outer public fields, bounded nested capsule shapes, pair/sample scope and lack of canonical decision authority. Database archival validation does not itself assert cryptographic validity; the shared domain rechecks crypto before any product reading or intake. Existing owner RLS and anonymous denial remain intact. Current format 15 carries real Event facts through codec/export/restore; timestamp-only replay preserves original occurrence. Sample facts stay partitioned and outside personal restore. No signing keys or grants are persisted. Production remains pending P1.

The bounded scope is two declared parties, immutable exchange snapshots and local attributed readings. Live synchronization, organizational identity, global thread ownership, automatic consensus, legal agreement and automatic source acceptance remain outside this phase.
