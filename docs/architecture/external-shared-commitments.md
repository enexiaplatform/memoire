# External shared commitments

M24 reuses the existing canonical Commitment for an owner's promise and the immutable Event log for issuance. An issued statement is a deliberate snapshot disclosure with its own UUID, issuance time, public promise reference, declared issuing/recipient parties, responsible person, text, due date, status and optional existing completion evidence text. Source update time is provenance; internal account, Opportunity, thread, raw source, money and database owner references are excluded from the exchange file. Exact allowlists reject unexpected fields. A missing due date or evidence remains null.

The owner previews the exact fields, selects whether to include existing completion evidence and confirms before issuance. The command reloads local canonical storage and refuses a stale preview or foreign/sample source. Required durable Event storage occurs before success. The issued Event records a local source commitment link for audit; the downloaded statement omits that private ID. Events are immutable at the database, remain owner-only under existing RLS and introduce no mutable aggregate or State Revision. Current backup format 15 and Event export/restore retain real issuance history. Sample statements carry a visible sample marker, remain partitioned and are excluded from personal restore.

Review contains a folded External promise statements panel alongside existing sharing. Issuance means the browser recorded a statement; download means a file was produced. Neither claims delivery, recipient acceptance, legal agreement or organizational identity verification. Party references and labels are supplied declarations. Completion evidence is the issuer's disclosed assertion and may need independent validation. Recipients can inspect JSON, confirm their agreed recipient reference and explicitly receive it as an unaccepted M17 observation. The original statement is retained verbatim in the normalized observation payload; owner/sample/source identity makes exact retries safe. A matching party reference does not authenticate an organization.

Receipt occurrence uses the recipient's receipt time; the issuer's issuance/source times remain reported data. No external timestamp grants access to canonical historical truth. The recipient's own Commitment, Evidence, Decision and completion state remain under their own commands and confirmation. Observations contain no local canonical subject links. A recipient receives only the explicitly shared statement, retaining their own storage and authority. This exchange does not create a shared cross-company database.

Statements are immutable readings rather than a globally ordered current-state stream. A changed promise needs a new issuance identity. The system does not silently infer supersession, consensus, dispute resolution, company identity or a legally binding signature. M25 addresses integrity capsules; M26–M28 address interoperable relationship/protocol boundaries. The bounded transport is file/JSON exchange through a channel chosen by the person. There is no automatic external send, directory, OAuth connector or recipient access expansion.

The migration adds only an invoker trigger on the existing Event table to validate bounded exact publication shapes and prevent client rewrites/deletion. Timestamp-only replay preserves original facts for idempotent backup recovery. No private-table permissions are widened. Production remains pending P1.
