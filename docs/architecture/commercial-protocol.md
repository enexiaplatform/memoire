# Commercial protocol architecture

M28 adds a bounded public wire contract over existing M24 promise statements, M25 capsules, M26 party/outcome scope and M27 issuer-local prerequisite assessments. [Protocol v1](../protocol/commercial-v1.md) defines all ten requested primitives, normalization/signing bytes, transport identity, privacy, authority and version boundaries. [The example](../protocol/commercial-v1.example.json) is a deterministic conformance fixture, not a client agreement or authenticated company statement.

`commercialProtocol.ts` validates and normalizes wire content, reuses capsule cryptography, adapts public M27 state and prepares M17 receipt envelopes. `commercialProtocolCommands.ts` checks owner-scoped issued history for export, confirms recipient intake and derives receipt-time history with conflict/predecessor visibility. Neither module imports a business resolver or creates alternate requirement/money/decision rules. Scope and graph checks validate the wire, not commercial truth.

Persistence is deliberately unchanged. Download is a pure artifact from a confirmed immutable public disclosure. Recipient import writes only an existing unaccepted observation Event. The complete message, its provenance and signature travel through existing local durability, owner RLS, immutable database receipts and format-15 backup/export. SQL archive guards do not imply cryptographic certification: protocol bytes are verified again when used. No migration, mutable entity, backup format or historical source is added.

Review extends the existing Cross-company prerequisites panel with a download and folded checked intake. Private internal IDs, raw canonical Evidence and undisclosed Condition/Money data are not added. A message is an issuer declaration and grants no recipient authority. Whole-message signing uses the same SPKI/P1363 WebCrypto helpers as capsules; private keys remain in host custody. Signature and integrity checks do not prove organizational identity or accepted outcomes.

The API/SDK carry the observation envelope through existing receipt transport; they do not expose the application's stores or automatically adopt protocol claims. Agents retain the same read/propose/explicitly granted original-observation boundaries. No agent proposal, message signature, webhook acknowledgement or receipt promotes external data to canonical truth.

Conformance/durability tests cover every field family, source privacy, reference integrity, normalization/order, authority refusal, tampering, nested capsules, independent keys, exact receipt retries, local failure, export/restore, sample isolation, receipt cutoffs, identity conflicts and predecessor gaps. Real migrated database tests exercise SDK/API receipt, RLS, immutability and fresh-chain recovery. Product browser checks cover download, tamper/key refusal, check-before-confirm, independent receipt/retry, reload and narrow layout. The final audit and complete architecture are recorded in [the completion gate](../qa/master-roadmap-final-completion-2026-10-01.md) and [system map](memoire-final-system-map.md).
