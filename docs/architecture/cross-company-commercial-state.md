# Cross-company commercial state

M27 derives a bounded shared assessment from the issuer's existing canonical Requirements, Conditions, Evidence and dependency graph. It reuses `projectOutcomeRequirements` for local resolution and `validateDependencyGraph` for the existing same-Opportunity graph. No second assessment engine or remote state authority is introduced. A person selects a verified M26 exchange, existing local requirements, public aliases, declared responsible parties and optional matching public promise references. Only existing active edges whose selected endpoints are disclosed enter the packet; at least one must span the declared parties.

The `memoire.cross-company-state` v1 packet contains that federation exchange, two to twenty selected public requirements and one to thirty prerequisites, bounded by the existing 20,000-character receipt transport. Public requirements preserve expected outcome, declared responsibility and the issuer's local `resolved`, `unresolved` or `conflicted` assessment. Private Opportunity, Requirement, dependency, Condition and Evidence IDs and raw Evidence are excluded. Selected requirement/outcome text and prerequisite explanation are visible in the exact preview and require explicit disclosure confirmation.

Mapping a prerequisite to a counterparty promise does not resolve it. A counterparty may report completion while the issuer's existing Requirement remains unresolved because its own Condition/Evidence has not independently supported it. The derived view shows both assessments and their source statement identities. Multiple reported statuses remain multiple claims. The issuer's selected requirements can be satisfied under its own assessment, while `sharedOutcomeConfirmed` and `acceptedCommercialTruth` remain false. Another company never acquires control over the issuer's Conditions, Evidence, Decisions or commercial truth through an exchange.

Preview reloads and validates existing canonical collections, exact owner/sample and same-Opportunity scope, actual graph integrity and the selected federation source. A fingerprint binds the complete local source reading; issuance recomputes the public projection, checks the canonical basis again after asynchronous verification and refuses stale or altered disclosures. The conservative fingerprint includes all owned Evidence, so a change to unrelated Evidence may require a fresh preview. It never exports that fingerprint or underlying private sources.

Only immutable issuance Events are new persisted facts. An Event records the issuer's private Opportunity link for audit; public JSON omits it. There is no new mutable canonical aggregate, State Revision or alternative dependency table. Existing canonical sources retain their own required history/RLS/backup contracts. Required Event durability precedes success; same-content retry is unchanged, conflicting identity is refused. Received assessments reuse M17's unaccepted observation Events with no recipient canonical subject links. Current backup format 15 preserves real publication and receipt facts; sample scope remains partitioned and personal restore excludes samples.

Review contains a folded Cross-company prerequisites panel. It reads existing requirements/prerequisites recorded in Opportunity, previews the exact graph slice and local assessments, confirms issuance, downloads, receives and displays attributed claims. It does not create missing dependencies to make an exchange look complete. Success language leaves delivery, counterparty acceptance and shared completion unconfirmed. Each party can receive an interoperable artifact while keeping its own internal database and authoritative assessments.

The migration adds an invoker guard for immutable Event envelopes, bounded public requirements/prerequisite references and issuer-local authority. Database archive checks do not confer cryptographic or canonical authority. The shared domain rechecks nested federation/capsule integrity before use and refuses unknown wire fields, reference errors, duplicate edges, loops or authority forgery. Existing private RLS remains intact. Issuer timestamps remain claims; receipt occurrence uses the receiving workspace's current time. Production remains pending P1.

The bounded scope excludes consensus, automatic dependency execution, cross-company write access, organizational identity certification, outcome acceptance by another company and automatic promotion of source claims. Human-confirmed existing canonical commands remain required for accepted Evidence or consequential commercial changes.
