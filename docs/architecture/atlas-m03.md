# Atlas receiver operations

Configure MEMOIRE_ATLAS_MAPPING as server-side JSON. Required fields are issuer (canonical Memoire Supabase origin), user (verified login UUID), workspace (native workspace UUID), owner (resolved data-owner UUID), origin (Atlas HTTPS origin), organization, atlasWorkspace, servicePrincipal and permissions (array containing the authorized subset of reference.read, reference.pin and events.sync). The Atlas principal must have exactly one membership, with consumer role. Missing mappings fail closed.

Before enabling the receiver, apply 20261125010000_atlas_consumer_state.sql after the receipt migration using the isolated Memoire migration owner. Provision a random independent 32-byte MEMOIRE_ATLAS_PROGRESS_KEY in the secret manager. In a parameterized operator transaction insert the approved owner, organization, Atlas workspace, principal and sha256(convert_to(bound_key,'UTF8')) into memoire_private.atlas_receiver_keys. Only the provisioning owner may change this table. Keep the plaintext out of SQL logs. The independent MEMOIRE_ATLAS_CONSUMER_KEY is issued by Atlas. Disable request body and authorization logging on both services.

Run node scripts/poll-atlas-reference.mjs from an authorized scheduler with MEMOIRE_RECEIVER_ORIGIN, MEMOIRE_POLL_WORKSPACE and a short-lived MEMOIRE_POLL_TOKEN for the mapped Memoire login. Supply fresh tokens via the approved issuer. Each invocation processes up to ten pages. Schedule subsequent ticks to catch up. Overlapping operations use a row lock and expected cursor. Failures after state lookup back off from one second to five minutes. Monitor HTTP failures before state lookup at the scheduler, including issuer or credential rejection.

GET /api/commercial?resource=atlas-reference&diagnostics=1 requires the same bearer and native workspace header. It reports the last successful poll, durable checkpoint, consecutive failed polls, retry time, visible pending count capped at one page, credential status and catch-up state. Atlas filters the feed by current visibility. Display always fetches the asset again. A withdrawn asset may keep a historical ID and cannot be rendered. Resume from Memoire after a missed tick. A lost Atlas acknowledgement is retried on the next run. A no-longer-visible acknowledgement is skipped. The Atlas mirror is advisory.

For coordinated restore, stop polling and both writers, restore both stores into fresh isolated targets, compare scope, progress and visible Atlas event sequences before enabling the poller. If Memoire is ahead of a restored Atlas, leave polling suspended and restore a compatible pair or explicitly replay from an operator-reviewed earlier cursor. Rotation keeps the Atlas principal stable. Update the secret, verify diagnostics and resume. For progress-key rotation, pause polling, replace the private digest and secret together, verify diagnostics and resume. Roll back application code only with a compatible mapping and paused poller. Retain the additive tables until the restore window closes.
